给 AI 编程助手装一个「经验本」：pi /lesson 命令实战

2026-07-31

用 AI 编程助手（这里用的是 pi）排查问题有个通病：一次费尽九牛二虎之力搞定的环境难题——代理、TLS 证书、shell 路径——聊完那一刻知识密度最高，关掉会话后就慢慢蒸发。下次再撞上同类问题，又得从头查一遍。

这篇文章记录一个非常轻量的解法：给 pi 写一个 /lesson 斜杠命令，一句话标题就能生成带骨架的经验文件，并自动把索引维护进「每次会话都自动加载」的 AGENTS.md。核心收益不是「能记笔记」，而是索引永远和文件同步、且对助手常驻可见。

问题：经验聊完就蒸发

手写笔记当然可以，但有两个反人类的环节：

  • 索引漂移：文件越写越多，目录/索引页长期跟不上，最后谁也懒得维护，笔记等于没有。
  • 对助手不可见：就算你记了，下次新会话里的助手根本不知道这些经验存在，照样重复踩坑。

第二个问题更关键——既然每天都在和助手对话，让它「记得」自己曾经解决过什么，比给人看的笔记更有杠杆。

设计：正文 + 常驻索引，二合一

pi 约定 ~/.pi/agent/AGENTS.md 是用户级上下文文件，每个会话启动时自动读进系统提示。所以把它当成「索引页」最合适：只放高复用的索引与摘要，正文放进 lesson/ 子目录。

~/.pi/agent/
├── AGENTS.md                  # 每次会话自动加载：环境 + 索引表
├── lesson/                    # 经验正文（一篇一个文件）
│   └── network-proxy-tls-ca.md
└── extensions/
    └── lesson.ts              # /lesson 命令（pi 扩展）

目标：跑一次 /lesson <标题>，同时完成「建模板文件」和「往索引表插一行」，彻底消灭手动维护索引这件事。

机制：pi 扩展三件套

pi 的扩展是一个导出默认工厂函数的 TypeScript 模块，用 jiti 加载，无需编译。

1. 自动发现 + 热重载

放在 ~/.pi/agent/extensions/*.ts 就是全局扩展，所有项目生效。改完不用重启 pi，一条 /reload 即时生效——这对迭代小工具非常友好。

2. registerCommand 注册斜杠命令

import type { ExtensionAPI } from "@earendil-works/pi-coding-agent";

export default function (pi: ExtensionAPI) {
  pi.registerCommand("lesson", {
    description: "记录新经验：生成模板并更新 AGENTS.md 索引",
    handler: async (args, ctx) => {
      // args: 命令后的文本；ctx.ui: 与用户交互；ctx.hasUI: 是否有界面
    },
  });
}

3. ctx.ui 做交互

命令处理器拿到的 ctx.ui 提供对话框，签名很直白（记一下，notify 没有 "success"，只有 info/warning/error）：

input(title: string, placeholder?: string): Promise<string | undefined>
notify(message: string, type?: "info" | "warning" | "error"): void

命令行为

  1. 标题：取自命令参数，没给就弹 input 交互式输入。
  2. 摘要：再问一句「一句话摘要」，用于索引表。
  3. 在 lesson/ 生成 <slug>.md，内置「背景/根因/解决方案/验证/注意」骨架。
  4. 往 AGENTS.md 的索引表置顶插一行，按链接去重。

关键实现

slugify：标题转文件名（保留中文）

用 Unicode 属性转义 \p{L}\p{N} 保留所有字母与数字（含中文），其余折叠成 -。中文标题直接得到中文文件名，跨工具也没问题。

function slugify(s: string): string {
  return s.toLowerCase()
    .replace(/[^\p{L}\p{N}]+/gu, "-")   // 保留字母/数字(含中文)
    .replace(/-{2,}/g, "-")
    .replace(/^-+|-+$/g, "")
    .slice(0, 60) || "lesson";
}

ensureIndexRow：置顶 + 去重 + 缺表自建

这是整个命令的价值所在。逻辑分三种情况，保证幂等（重复跑不会刷屏）：

  • 链接已存在：直接返回，不重复加。
  • 有 Lessons 区块和表：找到 |---|---|---| 分隔行，紧随其后插入新行——新条目自然置顶。
  • 没有区块/表/甚至没有 AGENTS.md：自动补建标准表头。
function ensureIndexRow(relFile, title, summary) {
  const rel = `lesson/${relFile}`;
  const row = `| ${title} | [${rel}](${rel}) | ${summary} |`;
  let content = existsSync(AGENTS_MD) ? readFileSync(AGENTS_MD, "utf-8") : "";
  if (content.includes(`](${rel})`)) return;          // 去重

  const lines = content.split(/\r?\n/);
  const secIdx = lines.findIndex(l => l.trim() === "## Lessons / 经验手册");
  if (secIdx === -1) { /* 追加新区块 */ return; }

  // 区块内找分隔行，紧随其后插入（置顶）
  for (let i = secIdx + 1; i < lines.length; i++) {
    if (lines[i].trim() === "|---|---|---|") { lines.splice(i + 1, 0, row); break; }
    if (/^##\s/.test(lines[i].trim())) break;          // 进入了下一个区块
  }
  writeFileSync(AGENTS_MD, lines.join("\n"), "utf-8");
}

把上面拼起来

handler: async (args, ctx) => {
  let title = (args ?? "").trim()
    || (ctx.hasUI ? (await ctx.ui.input("经验标题", "简短主题")) ?? "" : "");
  if (!title) return ctx.ui.notify("已取消：标题为空", "warning");

  const summary = ctx.hasUI
    ? ((await ctx.ui.input("一句话摘要", "症状/要点")) ?? "").trim() : "";

  const file = `${slugify(title)}.md`;
  writeFileSync(join(LESSON_DIR, file), buildTemplate(title, summary), "utf-8");
  ensureIndexRow(file, title, summary);
  ctx.ui.notify(`已记录：${file}`, "info");
}

工作流

刚排查完一个问题后，两步走：

/lesson Git 合并冲突处理        # 标题直接跟在后面
/lesson                         # 或回车后交互式输入

第一步建好骨架 + 索引；第二步紧接着对助手说「把刚才的排查过程整理写入刚建的文件」——它就会把当前会话里的根因、命令、验证整理成正文。因为索引已经同步好了，你完全不用碰 AGENTS.md。

为什么比手写笔记强

维度手写笔记/lesson + AGENTS.md
索引维护手动，长期漂移命令自动置顶 + 去重
对助手可见不可见每次会话自动加载
正文产出全手写骨架自动 + 助手据对话补全
检索翻文件夹助手读索引即可定位

本质上，这是把「个人知识管理」嫁接到了 Agent 的上下文加载机制上：索引常驻、正文按需，既不撑爆系统提示，又让助手始终知道自己「曾经会什么」。整个扩展不到 150 行，却把一件原本反人类的事变成了顺手的一句命令。

附：文中 ctx.ui 签名、扩展热重载等细节见 pi 官方扩展文档；这套 lesson/ 目录本身就是用这个命令维护的，算是最直接的 dogfooding。
